# Security review — Stage 16

Status of CreatorCo's Phase 1 MVP security controls, written for a partner bank/NBFC's security and architecture team.
It records what is in place, what Stage 16 tested and changed, and what remains open. It is an internal engineering
review, not an independent penetration test; a formal external assessment is required before any live financial pilot
(CLAUDE.md §25).

Scope: the Next.js modular monolith (web app, API v1 for native apps, partner API, staff consoles), its PostgreSQL
database, background jobs and provider adapters. All providers run as mocks; no real financial data is processed.

## 1. Architecture controls

| Area              | Control                                                                                                                                                                                                                                                                                                    |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Domain separation | Regulated financial data lives in the `fin` schema, read and written only by `financial-eligibility`, `underwriting` and `lending`. Creator-professional data stays in `public`; control-plane config in `ops` (no personal data, no secrets); analytics in `analytics` (pseudonymous, never reads `fin`). |
| Authentication    | Self-managed: scrypt password hashes, opaque session tokens (SHA-256 stored), `__Host-` cookies in secure environments, separate web (cookie) and native (bearer) session channels, per-account lockout after 5 failures in 15 minutes.                                                                    |
| Authorisation     | Roles read from the database on every request (`requireCreator`, `requireAdmin`, `requireOpsAdmin`, `requirePartnershipsAdmin`, `requireInsightsViewer`, `requirePartner`). Creators can only address their own records (services filter by user). Staff consoles return 404 to other roles.               |
| Four-eyes         | Provider routing/config changes, partner API keys, webhook URLs and the simulated lender policy need a second staff member.                                                                                                                                                                                |
| Consent           | Purpose-specific, versioned consents with receipts; withdrawal erases the purpose's data (with retention holds for open lender relationships).                                                                                                                                                             |
| Secrets           | Environment only. The database stores env var names (`INTEGRATION_*`), hashed partner keys and derived (never stored) webhook secrets. Staging/production refuse to start without their keys.                                                                                                              |
| Partner API       | 256-bit API keys (hashed, shown once, maker-checker), scopes, environment binding, HMAC-signed thin webhooks (ids only), SSRF checks on delivery.                                                                                                                                                          |
| Sensitive data    | No full PAN, Aadhaar, bureau report or card data stored. AA line items only in `fin`, AES-256-GCM sealed, bound to the AA data-life, live retention behind a switch. See docs/DATA_CLASSIFICATION.md.                                                                                                      |

## 2. Stage 16 changes

| #   | Area           | Change                                                                                                                                                                                                                                                                                                                                                                                                                                               | Evidence                                                                                     |
| --- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 1   | Access control | Route-guard inventory: every page, route handler and server action must call a guard (AST check) or be on a reasoned public list. Cross-creator API test: another creator's check and consent receipt are refused and never echoed.                                                                                                                                                                                                                  | `tests/unit/route-guards.test.ts`, `e2e/api.spec.ts`                                         |
| 2   | Abuse          | Rate limits in Postgres: sign-up 30/h and sign-in 60/10 min per network; OTP send 20/h per network; OTP verify 30/h, eligibility start 10/day, Access requests 20/day and app events 300/h per account; partner API 600/min per partner; signed-out page views capped for analytics. Keyed hash of the IP (IPv6 per /64), never stored raw; 48-hour retention. Counted after validation. Fails open if counting fails (business limits still apply). | `modules/rate-limit`, `tests/integration/rate-limit.test.ts`, `tests/unit/client-ip.test.ts` |
| 3   | Browser        | Strict CSP with a per-request nonce and `strict-dynamic`; no third-party origins; `frame-ancestors 'none'`, `form-action 'self'`, `object-src 'none'`; deny-all CSP on APIs; COOP/CORP; HSTS; tighter Permissions-Policy. A JavaScript-free global error page.                                                                                                                                                                                       | `src/lib/csp.ts`, `src/proxy.ts`, `e2e/security.spec.ts` (no CSP violations on real pages)   |
| 4   | API input      | JSON bodies capped at 16 KB while streaming (oversized bodies are refused before they're buffered).                                                                                                                                                                                                                                                                                                                                                  | `e2e/security.spec.ts`                                                                       |
| 5   | Logs           | Database errors redacted everywhere they could be logged: Drizzle parameters (including multi-line values), Postgres key values and quoted input values. Applies to our logger, job errors (shown in `/ops`) and the framework's own error output.                                                                                                                                                                                                   | `src/lib/log-redaction.ts`, `tests/unit/log-redaction.test.ts`                               |
| 6   | Database       | Least-privilege role `creatorco_app`: rows only — no CREATE/ALTER/DROP/TRUNCATE, no migration history — with an explicit RLS policy on every table; grants re-applied after every migration run. The full E2E suite (68 tests) passes with the app connected as this role.                                                                                                                                                                           | `0036_stage16_app_role.sql`, `tests/integration/app-role.test.ts`                            |
| 7   | Retention      | Security records purged: sign-in attempts and ended sessions after 180 days (CERT-In ICT log period), verification codes after 30 days. Data inventory with every table classified (test-enforced).                                                                                                                                                                                                                                                  | `modules/identity/housekeeping.ts`, `docs/DATA_CLASSIFICATION.md`                            |
| 8   | Environment    | A production build with `APP_ENV` unset is treated as production (fails closed: no development keys or loosened limits).                                                                                                                                                                                                                                                                                                                             | `src/lib/app-env.ts`                                                                         |
| 9   | Dependencies   | Next.js 16.3.8 → 16.4.3 and Zod → 4.6.7 for published advisories (incl. critical Next.js RCE advisories in features this app doesn't use). `npm audit --omit=dev`: 0 vulnerabilities. Git history scanned for credentials: none.                                                                                                                                                                                                                     | `package.json`                                                                               |
| 10  | Accessibility  | axe WCAG 2.1 A/AA checks on public, creator (dark and light), risk, ops and partnerships screens; two label-in-name issues fixed.                                                                                                                                                                                                                                                                                                                    | `e2e/accessibility.spec.ts`                                                                  |

An independent internal review of the Stage 16 changes found no high-severity issues; its medium findings (free-text
campaign tags reaching analytics, multi-line parameter redaction, client-IP trust and shared buckets, sign-up limits
for shared networks) were fixed before hand-off.

## 3. Residual risks and open items

| Item                                   | Risk                                                                                                                                                                          | Plan                                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Staff MFA                              | Staff (risk, ops, partnerships, analyst) sign in with a password only. They can read creator data and approve routing/key changes (four-eyes reduces, not removes, the risk). | Deferred (decision). Before live data: SSO with MFA at the identity provider, or TOTP in-app. |
| Client IP trust                        | Network rate limits trust the edge's `x-forwarded-for`. Behind a proxy that appends, `CLIENT_IP_TRUSTED_HOPS` must be set; `next start` must never be exposed directly.       | Deployment checklist (Stage 17).                                                              |
| Rate-limit fail-open                   | If the counter table is unavailable, requests are allowed.                                                                                                                    | Monitor `rate_limit.failed`; per-account lockout and OTP/bureau limits still apply.           |
| Account enumeration                    | Sign-up says when an email is already registered; OTP says when a number is verified elsewhere.                                                                               | Rate limited; email verification and generic messages come with the notification provider.    |
| No email verification / password reset | Account recovery and email ownership aren't proven.                                                                                                                           | With the notification vendor.                                                                 |
| Partner network controls               | No mTLS / IP allow-list for partner calls.                                                                                                                                    | At the gateway with the first live partner.                                                   |
| Webhook DNS rebinding                  | Small window between the SSRF check and connection.                                                                                                                           | Egress proxy that pins addresses.                                                             |
| Account closure                        | No self-serve deletion; identity, profile and points records stay while the account exists.                                                                                   | Counsel to set the closure and retention schedule.                                            |
| Retention periods                      | Consent, audit, provider-request and closed lender records have no fixed period yet.                                                                                          | Counsel / partner lender.                                                                     |
| Pre-auth abuse                         | No CAPTCHA or bot challenge.                                                                                                                                                  | Add at the edge if sign-up abuse appears.                                                     |
| Dev tooling                            | `drizzle-kit` (dev only) pulls an old esbuild with a moderate dev-server advisory; not shipped or run in production.                                                          | Track the drizzle-kit release.                                                                |
| Formal testing                         | This is an internal review.                                                                                                                                                   | External penetration test before a live pilot.                                                |

## 4. Deployment requirements (for Stage 17)

- `APP_ENV=staging|production`; all keys set: `PAN_FINGERPRINT_SECRET`, `FI_DATA_ENCRYPTION_KEY`,
  `PARTNER_WEBHOOK_ROOT_KEY`, `ANALYTICS_PSEUDONYM_KEY`, `RATE_LIMIT_KEY`, `CRON_SECRET`.
- Two database credentials: the schema owner as `DATABASE_MIGRATION_URL` (migrations, `db:check`), and the app as a
  login user that is a member of `creatorco_app` (`DATABASE_URL`). The migration user needs `CREATEROLE` once to create
  `creatorco_app`, or create the role beforehand.
- Behind an edge that sets `x-forwarded-for` (Vercel) or with `CLIENT_IP_TRUSTED_HOPS` set to the number of appending
  proxies. HTTPS only.
- Scheduled `GET /api/internal/cron/tick` (jobs include `rate_limit_purge` and `purge_auth_records`).
- `FI_LIVE_LINE_ITEM_RETENTION=false` until counsel and the partner lender sign off.
